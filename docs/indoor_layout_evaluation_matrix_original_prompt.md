# 任务：设计一个用于室内布局评价的量化分析矩阵与技术化操作方案

你的任务不是写一篇学术论文，而是设计一个**技术化的计划与操作指南**，用于构建一个能够评价室内空间布局的分析矩阵。这个矩阵应能够从二维平面布局出发，逐步发展到可迁移至 Rhino、Grasshopper 以及 VisualARQ / BIM 场景中的系统。

你需要认真理解我的要求，不要只给泛泛而谈的方案。你要自己做甄别、搜索、归纳和判断。我的很多描述本身是模糊的、情绪化的、尚未完全确定的，这些内容不能被你简单“规整掉”，因为这正是让大模型在足量信息内自己做判断的必要条件。

## 二、总体目标

我的目的其实是做一个**室内布局的评价矩阵**：

1. 生成各种能够量化描述空间布局的能力；
2. 再构造指标；
3. 用于后续的感知实验；
4. 并且最好能够服务于正向设计与反向分析；
5. 最终能迁移到 BIM 场景中。

也就是说，当我有一个布局的时候，我可以将这个分析矩阵套上去，然后获得量化指标。用户可能需要手动拾取一些东西，或者指定一些属性；分析矩阵也可以根据这些属性生成结果，或者直接分析几何体生成这些结果。你要好好列出这些可能路径。

## 三、空间层级：这个东西至少要包含的层级

这个评价系统至少包含以下层级。你要思考这些层级之间如何互相嵌套、关联、计算和转换。

### 1. 单个家具

例如一把椅子、一张桌子、一个柜子、一个沙发等。

需要考虑：

- 家具自身的几何属性；
- 家具方向；
- 家具尺度；
- 家具与其他家具的距离；
- 家具与区域边界、路径、柱网、房间边界的关系。

---

### 2. 常规家具组

例如：

- 桌椅组；
- 沙发茶几组；
- 餐桌椅组；
- 办公桌椅组；
- 床与床头柜组等。

当前前两个层级可以是一体的，例如有时候不需要单独识别“单个家具”，而是直接识别“家具组”。

你要考虑：

- 家具组如何定义；
- 家具组如何从单个家具推导出来；
- 家具组是否需要人工标注；
- 家具组是否可以通过距离、方向、功能关系、拓扑关系自动识别；
- 家具组的边界如何生成；
- 家具组的内部 order 程度如何计算。

---

### 3. 家具组之间形成的区域

家具组之间可能形成更大的区域，例如：

- 会客区；
- 餐饮区；
- 工作区；
- 休息区；
- 展示区；
- 等候区等。

这个层级要包含：

- 区域的形态；
- 区域之间的关系；
- 区域内部路线的表示。

我认为区域内部路线可以用一个网络系统来表示。你要思考这个网络系统如何生成，比如：

- 基于可通行空间；
- 基于家具之间的间隙；
- 基于区域边界；
- 基于人流可能路径；
- 基于 medial axis / skeleton / visibility graph / navigation graph / space syntax 等理论或方法。

---

### 4. 区域之间的通路

区域之间的通路，也就是区域之间隔出来的路线。

你要特别仔细思考：

- 当区域之间的间隔出现 XXX 的尺寸，或者类似规则的时候，是否就不再将它们视为一个区域？
- 什么时候这个间隔是路径？
- 什么时候这个间隔只是家具组内部的缝隙？
- 什么时候路径会把两个区域拆开？
- 什么时候边界又能将两个隔着的东西拉到一块去？
- 怎样算一个区域，怎样不算一个区域？

当前最简单的方法可能是：

- 用边界；
- 用东西之间的距离；
- 看路径够不够宽；
- 够宽就拆分路径。

但是你得仔细思考，不能只停留在这个粗糙规则上。

---

### 5. 柱网系统

系统需要考虑柱网。

包括：

- 常规正交柱网；
- 非正交柱网；
- 异形柱网；
- 柱网不完整的情况；
- 柱网与区域、家具组、整体空间势之间的关系。

你要考虑：

- 柱网如何被表达为一种“势”；
- 区域如何与柱网产生 alignment；
- 如果柱网是异形的，或者区域是异形的，也可以产生 alignment 关联；
- 所以这种关联性应该是连续值，而不是简单的“对齐 / 不对齐”。

可以参考 OCTA，或者基于它发展。

### 6. 整个房间的边界

包括：

- 墙体；

- 内部限制条件；
- 开口；
- 门窗；
- 不规则边界；
- 斜墙；
- 曲线墙；
- 房间边界与区域边界、家具组边界、柱网之间的关系。

你要考虑整个房间边界如何影响：

- 家具布局的整体势；
- 路径系统；

### 7. Boundary 系统

需要设计一个 boundary 系统，用于描述区域的边界。

这里的 boundary 不只是墙，而是广义边界。

边界应至少包含以下属性：

- 是否有厚度；
- 厚度是多少；
- 是否可以看穿过去；
- 是否可以走过去；
- 是否阻挡路径；
- 是否阻挡视线；
- 是否具有入口；
- 入口在哪里；
- 入口宽度是多少；
- 边界是否连续；
- 边界是否只是视觉边界；
- 边界是否只是材质边界；
- 边界是否只是色彩边界；
- 边界对区域归属感的影响。

我举几个例子：

#### 例子 1：地毯边界

地面涂上相同颜色的地毯，这也是一种边界。

它可能具有以下属性：

- 无厚度；
- 可走；
- 可看过去；
- 不阻挡通行；
- 不阻挡视线；
- 但它仍然形成一种区域边界。

你可能需要设计一种新的属性来描述这个地毯状态有什么是它有、其他边界没有的。

例如这可能涉及：

- 材质连续性；
- 颜色连续性；
- 地面符号性；
- 区域归属提示；
- 视觉分组作用；
- perceptual grouping；
- surface cue；
- territorial cue；
- semantic boundary 等。

你要自己判断用什么概念比较合适。

#### 例子 2：矮柜边界

矮柜可以看过去，有厚度，不能走过去。

注意这种边界是要开入口的，入口也可以是边界的属性之一。

它可能具有：

- 一定厚度；
- 阻挡通行；
- 不完全阻挡视线；
- 可看过去；
- 需要入口；
- 入口可以成为边界系统中的一个属性；
- 它既是家具，也是边界。

#### 例子 3：玻璃墙边界

玻璃墙可以看过去，不能走过去，有比较小的厚度，相比于矮柜来说。

它可能具有：

- 较小厚度；
- 强通行阻隔；
- 弱视觉阻隔；
- 高透明度；
- 边界明确；
- 可能具有门或入口。

## 四、需要能够量化表示的内容

能够量化表示的东西至少包含以下几种。

---

### 1. 区域内部家具组的 order 程度

需要评价区域内部家具组的 order 程度。

注意：

- 即便家具区域的边界是斜着的，其内部的整齐度也是依赖于这个斜着的边界；
- 也就是说，它是仅就区域内部而论的 order；
- 在多数情况下可能是有一个边是斜的这样；
- 这不是简单地相对于全局坐标轴判断整齐；
- 而是要相对于该区域自身的局部边界、局部方向、局部势来判断。

这里还有一个正反设计问题：

- 区域由物体组成；
- 所以有时候既是在评价物体；
- 又能够量化家具组成的区域的形态。

你要处理这种互相定义的问题。

对于 order 的计算可以参考 OCTA，或基于它的设计发展出来。

---

### 2. 路径与区域拆分

路径应该是这样：

当区域之间的间隔出现 XXX 的尺寸，或者类似规则的时候，就不再将它们视为一个区域了。但是边界又能将两个隔着的拉到一块去。

这里涉及一个问题：

- 怎样算一个区域？
- 怎样不算一个区域？
- 什么东西将两个区域拆开？
- 什么东西又把两个区域归为一类？
- 路径的宽度如何影响区域判断？
- 边界如何影响区域判断？
- 家具之间的距离如何影响区域判断？
- 人的可通行性如何影响区域判断？
- 视觉连续性如何影响区域判断？
- 功能归属如何影响区域判断？

当前最简单的方法就是：

- 用边界；
- 和东西之间的距离；
- 看路径够不够宽；
- 够宽就拆分路径。

但是你得仔细思考。

你不能直接给一个死阈值，比如“超过 1.2m 就算路径”。我的目的在评价中是不引入任何人工设置的阈值或限制。更好的方案是输出连续值。

---

### 3. 区域与区域之间的 alignment 程度

需要评价区域与区域之间的 alignment 程度。

这里 alignment 不是简单说“是否对齐”，而是家具组组成的总体的势是否对齐。

你要考虑：

- 什么是势？
- 区域的势如何定义？
- 家具组的势如何定义？
- 边界的势如何定义？
- 路径的势如何定义？
- 如果区域势一致，就差不多对齐；
- 如果不一致，就差不多没对齐；
- 但最好输出连续值，而不是二元判断。

还要考虑：

- 如果边界是异形的咋整？
- 如果边界是斜的咋整？
- 如果区域不是矩形咋整？
- 如果区域是弯的、碎的、多个局部方向咋整？
- 如果区域有多个主方向咋整？

---

### 4. 区域和柱网系统的对齐程度

同样是势。

看看区域的势是否与柱网对齐。

但是：

- 柱网如果是异形的；
- 或者区域是异形的；
- 也可以产生 alignment 关联。

所以说关联性应该是连续值，可以参考 OCTA。

你要考虑：

- 柱网势如何提取；
- 区域势如何提取；
- 两者如何比较；
- 多方向柱网如何处理；
- 局部柱网如何处理；
- 缺失柱网如何处理；
- 非正交柱网如何处理；
- 异形柱网如何处理。

---

### 5. 整体空间的家具组成的势由什么控制

需要思考：

- 整体空间的家具组成的势由什么控制？
- 是由家具组控制？
- 是由路径控制？
- 是由边界控制？
- 是由房间轮廓控制？
- 是由柱网控制？
- 是由最大区域控制？
- 是由多个区域势叠加控制？
- 是由主要通路控制？
- 是由人的运动方向控制？

还要评价：

- 整体空间的势是否与柱网的势相一致；
- 一致到什么程度；
- 是否可以输出连续值；
- 是否可以用多尺度方法表示；
- 是否可以同时表示局部势和全局势。

---

### 6. 让出的路径的连通性如何

需要评价让出的路径的连通性。

但具体连通什么，需要你来考虑。

我的建议是你至少考虑：

- 区域与区域之间是否连通；
- 入口与各区域是否连通；
- 主要路径是否连通；
- 家具组之间的可达性；
- 人是否能从一个区域到另一个区域；
- 路径网络是否有断裂；
- 路径是否绕行；
- 路径是否形成环路；
- 路径是否有死胡同；
- 路径宽度是否连续变化；
- 路径是否受边界透明性、可通行性影响；
- 视觉连通性和行动连通性是否分开计算。

这里可能需要图论、visibility graph、space syntax、navigation mesh、medial axis、Voronoi、skeletonization、accessibility graph 等方法。你需要判断哪些适合。

## 五、关于阈值、连续值和客观性

我的一个核心要求是：

不要在评价中引入任何人工设置的阈值或限制。

也就是说：

- 不要简单规定“超过多少米就是路径”；
- 不要简单规定“角度差小于多少就是对齐”；
- 不要简单规定“距离小于多少就是一组家具”；
- 不要简单规定“连通性达到多少就是好”。

理想上，如果能做“是否一致，是否符合”这样的描述当然最好；但是更好的方案是输出一个连续值。

我的目的是：

- 所有指标都是基于当前的布局排列生成的；
- 是客观的；
- 是一种对于空间布局的量化描述；
- 不依赖人工硬阈值；
- 可以用于后续感知实验；
- 后续再通过实验检验这些连续指标是否与人的感知相关。

如果有些地方确实无法避免参数或阈值，你必须明确说明：

1. 这个参数是什么；
2. 为什么无法避免；
3. 它是否可以从当前布局自适应生成；
4. 它是否可以通过数据驱动方式估计；
5. 它是否应该通过感知实验定夺；
6. 它是否应该通过搜索相关论文来定夺。

例如：

- 隔了多远就不算一个区域了；
- 路径多宽才开始明显分割区域；
- 多透明算可看过去；
- 某个 boundary 是否足以产生区域感；
- 家具距离多近才算一个组。

这些如果最终完全无法确定，也应汇报。

## 八、正向设计与反向设计的互逆性

理想上，正向设计与反向设计是可以互逆的。

也就是说：

### 反向分析

当我已有一个布局时：

- 输入布局；
- 识别家具；
