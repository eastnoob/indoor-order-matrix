## First-slice contract: candidate to explicit choice

Input is one immutable source scene, its exact source revision (SHA-256 over canonical `scene.to_dict()` bytes including context, units, plane, source objects, geometry and openings), an explicit B2 request when inference is requested, zero or more authored candidates, and session actions. Candidate identity is `(candidate_id, candidate_version_id)`; each version retains source type `authored`/`inferred`, source IDs, geometry refs or exact polygon, B2 request/scenario ID, source revision, plane identity (full origin and basis, not just name), length units, evidence/refusal reasons and diagnostic component references. A derived result hash also binds B2 evidence to its request. IDs are stable within the session; a replacement has a new version and a link to the old version. A user-drawn closed curve is a future **authored provisional input** through the same gate, not an already available UI capability.

The preview lists **scope proposals**, not their nested contours, as selectable units. For the accepted real snapshot, the list has one S1 row; C1–C5 are diagnostic children, never five selectable rooms. The unfilled exterior of S1 remains the analysis *scope* including wall and column locations. Neither the contour interior nor a future free-space subtraction replaces it. For several separate qualified scope candidates, all remain visible and `selected_candidate_id` stays null until an explicit choice. A singleton also starts null. An authored candidate has precedence as source intent; an inferred candidate remains visible, but an incompatible authored/inferred pair blocks switching until the user makes an explicit qualified choice that records both IDs and the disagreement. No score, timestamp, lexical ID, candidate count or color chooses a winner.

Session action vocabulary is deliberately small: `select(candidate_version_id)` is ephemeral UI focus; `confirm(candidate_version_id, expected_session_revision, expected_source_revision, expected_plane_identity, action_id, actor, time, reason)` and `replace(old_version_id, new_candidate_version, expected_session_revision, expected_source_revision, action_id, actor, time, reason)` are state-changing attempts. The in-memory session projection starts at `session_revision=0`. An accepted first/different confirmation, accepted replacement, or newly recorded unresolved action conflict increments it once; hover/select, refused attempts, and identical retry/reconfirmation effects do not. Each confirmation/replacement compares its expected revision with the current session revision **and** checks source revision, full plane identity, target candidate version and B2 request identity before changing state. This is a single-session atomic transition, not a database or concurrency service. A duplicate identical action ID retains retry provenance with one effect; the same ID with different content retains both payloads, marks an unresolved conflict and blocks handoff. Two different confirmation attempts from the same old session revision cannot both change the current choice: after the first accepted transition, the second is retained as `stale_session_revision` and cannot replace it. A stale refused attempt alone is not treated as a semantic conflict with the already accepted choice. An independently detected unresolved authored/inferred or source-fact conflict still blocks handoff until a separately authorized resolution; event order does not choose a winner. The action log is append-only **in memory**; the effective current projection is derived. Switching back to an earlier still-qualified version is a new explicit `select` + `confirm` with the current session revision and source/frame identity, not an undo or inherited confirmation. An accepted replacement of the current version clears its active projection and leaves the replacement provisional; a **refused** replacement leaves a still-qualified current choice intact. No general undo, resolver-role model, persistence, restart durability or public serialization is in this slice.

| State/action | Display and handoff |
| --- | --- |
| Zero candidate, or no confirmed choice | Show source/diagnostic bounds only; `AnalysisDomain` handoff absent and domain-dependent computation `not_available`. |
| Hover or keyboard focus | Highlight outline and announce ID, source type, plane, status and reason; log and current choice unchanged. Green hover may be a visual focus cue only. |
| Click/list select | Mark one pending version, show exact outline, source IDs and qualification result; no active domain yet. |
| Confirm, qualified and fresh, matching session token | Record action, increment session revision for a new choice, establish exactly one session current version and produce bounded handoff. Display active state with text `Active: ID (authored/inferred)` plus visual style. |
| Refused confirm/replacement; source and frame unchanged | Record `attempt.status=refused` and reason without incrementing the session revision. Requalify the prior current choice and keep its `current.status=active` and handoff if still valid; if there was no prior choice, `current.status=not_available` and handoff is absent. The refused target never gets a handoff. |
| Refused attempt after source/frame changed | Record `attempt.status=refused`; retain the old choice as history but set `current.status=not_available` and return no consumable handoff. A new qualified confirmation against the new source/frame is required. |
| Accepted replacement or explicit switch | Keep prior version and action provenance. Replacing the current version clears the old effective choice, increments revision, and leaves the new version provisional/unconfirmed; a switch to an earlier qualified version needs a fresh confirmation at the current revision. |
| Same-ID incompatible claims or unresolved source conflict | Retain both claims and mark conflict with reasons. `current.status=conflict` and no handoff until separate resolution; no event-order winner. |

Hover, click and confirm must also be possible through a keyboard-operable candidate list and buttons with text labels and refusal reasons. Visual outline/color is redundant, not the only identity or state cue. The UI would render read-only projections and submit only these explicit actions; no UI code is proposed now.

## Qualification, handoff and refusal

Before activation, check: (1) expected session revision, exact source revision, B2 request identity and full analysis-plane identity still match; (2) existing `AnalysisContext` and explicit caller/user request provide compatible metre units, one verified analysis plane and the datum/cut needed for this scenario, without silently inferring a floor or mixing levels; (3) the candidate is one finite, positive-area, closed, valid polygon in that plane, with unambiguous present geometry refs where authored; (4) applicable source/derived B2 evidence is usable, with no local unresolved aperture, explicit unfilled opening, contradictory host/source fact, or relevant unsupported/partial geometry; (5) no unresolved choice conflict. Absence of an authored floor datum is retained as provenance/uncertainty and does not itself fail a caller-qualified single-plane candidate; a missing required caller plane/datum or incompatible frame does fail. `confirm` supplies authority, not missing facts. The accepted real S1 fails for its still-unresolved local A11/A12 aperture evidence; do not infer that its caller-supplied datum resolves those residuals. A simple complete authored or inferred single-plane candidate can pass without inventing a new global numeric threshold. Candidate polygon validity, source component connectivity, lifecycle and later field status remain four separate facts. A valid polygon alone is not a connected room or walkable route.

For an authored domain, derive the canonical candidate/preview outline from **the same uniquely resolved geometry refs** that the `AnalysisDomain` will use: project each referenced `MeshGeometry3D` with existing `plan_projection(mass_patch_from_mesh(mesh), plane)`, combine its actual components with `component_shape`, and require one finite valid polygon. If an authored outline was supplied separately, require topological `equals` against that projection before confirmation; do not use bounds, vertex hulls or an approximation. Refuse missing/duplicate refs, a disjoint `MultiPolygon`, or mismatched shape. A hole may pass only when the projection retains it exactly and the preview/selected polygon also contains it; otherwise refuse. Recompute from current refs and repeat the equality check immediately before handoff, along with source revision and plane checks, so a stale or mutated input cannot reuse a confirmation. Then reuse the existing `AnalysisDomain` and source geometry. For an inferred polygon, the proposed private helper materializes a **session-only derived support mesh**: use installed Shapely `constrained_delaunay_triangles` to tessellate the exact polygon, map plane-local `(x,y)` back through the recorded `AnalysisPlane`, then require `plan_projection(mass_patch_from_mesh(mesh), plane)` to be topologically `equals` to the selected candidate polygon both at confirmation and handoff. Reject any lost hole, disjoint part, non-finite coordinate, failed tessellation or unequal projection; do not repair or silently buffer. Give the derived `MeshGeometry3D` a distinct ID and provenance (`candidate_version_id`, source revision, plane, B2 request/hash, `derived_scope_not_physical_mass`), add it only to a `dataclasses.replace` session child, and point a current `AnalysisDomain` at it with `source_id=None`, `selection_method="explicit_session_confirmation_of_inferred_candidate"`. The child never goes back to the IFC, SVG or original source scene. Existing `_domain_shell_identity` will not identify a physical wall/column as the domain support, so their occupancy remains in `physical_occupancy`. The private handoff result must carry the **same exact verified polygon** separately: the ordinary view's `size` is only its bounding frame, not its exact boundary.

Suggested private entry: `_analysis_scene_view_with_domain_handoff(scene, *, candidates, session_state, action, expected_session_revision, expected_source_revision, b2_request=None) -> {attempt, current, session_revision, selected_candidate_id, analysis_domain, scope_polygon, preview, provenance}`. `session_state` is the current in-memory action log/current-choice projection; `action=None` is a read-only preview and needs no expected session revision. For confirm/replace, the expected session revision is required in the action **and** entry call and must agree; the helper computes the source revision again rather than trusting the supplied expected hash. It calls `_analysis_scene_view_with_semantic_enclosure` only when that explicit scenario is requested, qualifies the chosen version, constructs the session child, and calls existing `analysis_scene_view(child)` only for an eligible **current** choice. `attempt` reports accepted/refused and reason for the submitted target; `current` independently reports active/not_available/conflict and its candidate version. If a replacement attempt is refused but the previous choice requalifies against the unchanged source/frame, `analysis_domain`, `scope_polygon` and `preview` describe that previous choice. If there was no choice, or source/frame changed, these three fields are absent even though the old history is retained. `preview` copies just the selected outline, identity/status text and source-aligned occupancy/display records needed for inspection; the full analysis-view dict and session child stay internal. In particular the helper does **not** call or feed `evaluate_scene`, `infer_scene_evidence` or free-space/topology consumers in this slice, because their current rectangle and graph paths lack the exact selected-scope gate. A future B3 handoff must use the exact polygon and occupancy with explicit channel policy, not infer scope from `size` or `domain_available` alone.

The source scene remains immutable. B2 doors/windows are treated default-closed **only** for an explicitly requested semantic-enclosure scenario with caller authority and supplied datum/cut/contact/area budgets; this does not certify observed door state. Genuine unfilled openings remain open; ordinary beams/furniture cannot create enclosure; columns remain physical occupancy and only conditionally support boundary under B2 evidence. This slice calls the accepted helper and never reinterprets those rules. It chooses no implicit 1.5 m plane, contact tolerance, free-space backend, resolution, route width, space role or selector. A session choice establishes a traceable scope for later furniture-group/layout analysis; existing group evidence can be viewed against the selected boundary, but clipping, membership, route, field and metric behavior are not claimed or implemented here.
