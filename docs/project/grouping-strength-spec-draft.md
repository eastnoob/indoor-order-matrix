# AuthoredGroup 归属证据场与强度：Spec 草案

- 日期：2026-10-25；用户确认：2026-10-26
- 状态：**用户同意作为设计诊断基线；不构成生产契约或实现批准**
- 依据：[设计诊断](evidence/grouping-strength-design-diagnostic.md)、[实验协议](grouping-strength-design-experiment-protocol.md)

## 目标

核心输出是冻结作用域内的并行关系证据场，不为每个组给出“属于/不属于”的二值答案，也不选唯一获胜组织。描述每个合格 AuthoredGroup 在不同候选、尺度/查询下得到的支持、反对、冲突或未知证据；只有证据映射有依据时，才派生非概率归属强度读数。候选提议、成员证据、归属读数和组级 profile 是分开的结果。

## 拟定输入规则

以下规则经用户同意，作为本轮设计诊断基线；它们仍不是生产契约：

1. 只有来源可追的显式 `furniture_group` 标记（或 adapter 明确声明等价的标记）才使 AuthoredGroup 合格。不能仅凭组内对象都是家具推断资格。
2. 显式空组保留在输入审计中并标为 `empty_group`，但不成为候选节点，也不进入归属字段。
3. 同一对象在一个组内重复引用时，原始引用和重复诊断均保留；成员及证据计算只计一次。
4. 失效成员引用保留在输入审计中；受影响的成员证据标为 `invalid`、`partial` 或 `not_available` 并说明原因，不把该成员静默丢弃或改成负证据。
5. 同一物理对象可属于多个合格 AuthoredGroup。每个组保留该成员；共享来源作为依赖记录，物理观测不能因重复引用而重复投票。

当前 `analysis_scene_view` 和 `group_self_description` 的资格、空组及共享成员行为不一致。实现前必须让两者消费相同的成员身份语义，或明确记录为何需要不同视图。

## 候选、证据场与 profile

- 候选 recipe 产生提议视图 `P`，包含 recipe、冻结 scope、proposal extent、闭包/搜索状态及提议证据。extent 只表示该 recipe 提议的范围，不是真实成员标签或最终硬分区；不同 recipe 可以产生重叠或嵌套视图，且不产生唯一答案。
- 对每个候选、尺度/查询和冻结 scope 中的每个合格组，保留证据记录 `E(g, k, s)`。proposal extent 外但仍在 scope 内的组也有记录，并单列为边界张力。scope 外实体没有字段单元，不得赋值为零。
- `E` 按证据家族保存支持、反对、冲突、状态、来源、依赖和解释。一次物理观察被多个算子引用，不因此成为多条独立证据。
- `M_k(g, s)` 是可选的非概率读数。只有证据到读数的映射及量尺有可辩护依据时才生成；否则保留分家族证据和状态，不强行合成单一数值。
- 候选 profile 可概括其 proposal extent 内的场读数，并同时报告有效成员数、证据覆盖、状态计数和缺失原因；extent 外但仍在 scope 内的场单元继续保留，单列为边界张力。profile 是并行场的摘要，不把范围变成硬成员标签。均值、中位数、最弱成员是待比较的展示读数，不是已选定的生产公式。缺失值不以零填补；单成员也不会因候选提出而自动获得满分。

## 状态与互斥

- `unknown`、`conditional`、`partial`、`invalid`、`not_available`、`conflict` 和 `incomplete` 保持各自含义及原因，不转成数值零。`conditional` 需要说明来源或表示限制。
- 搜索完整度独立于证据状态。受限搜索不能宣称 recipe 闭包或穷尽。
- 来源可追、两端唯一解析且落在有效范围内的显式互斥声明，可否决两端共同进入同一候选。互斥不抹除任一端点自身的证据，也不影响其他候选。端点失效、歧义或越界时，声明保留为未决记录，不能作为硬否决。

## 验收边界

进入实现计划前，设计证据至少要回答：

- 输入规则在 canonical contract、`analysis_scene_view` 和 `group_self_description` 之间是否一致；否则保留最小反例和待定所有者决策。
- 每个候选的字段域是否覆盖全部 scope 内合格组，且所有无数值单元都有明确状态和原因。
- driver/modifier 扰动、互斥端点有效性、unknown/conditional/incomplete、提议证据与归属证据依赖、proposal extent 外边界张力是否有可复放诊断。
- 强核心/弱成员、缺失覆盖、singleton/低覆盖和重叠/嵌套候选 profile 是否能并列观察，且不把缺失变成零。

当前诊断尚未满足这些条件：只暂时支持候选层面的有效端点 veto；没有目标归属字段或 member profile。真实场景盲审及 Stage A 的 37 节点搜索成本比较留到设计证据稳定后。本草案不规定概率模型、训练拟合、生产 API、UI、真实场景校准或任何数值权重。
