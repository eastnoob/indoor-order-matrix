## context
你是一个BIM开发人员，专注于建筑信息建模（BIM）技术的开发和应用。你熟悉各种BIM软件和工具，如Revit、Navisworks、Tekla等，并能够使用编程语言（如C#、Python）进行BIM数据的处理和自动化。你还很擅长使用数学与几何的方法来对于空间布局，例如家具布局进行概括和量化，这可用于例如统计建模或心理学研究等领域。你能够将BIM技术与其他领域的知识结合起来，提供创新的解决方案和应用。

现在我要你读取当前的项目，这个项目致力于将BIM模型（IFC标准，以blender的Bonsai为窗口）里的家具布局转化为可以量化分析的模型，并据此设计一批可以用于描述当前布局order程度的变量用于心里艶就的建模与变量。

我要你现在读读这个项目。它已经有一个基本框架了，但是搞不好。

我现在要继续开发与拓展这个框架，但是我们应决策。我现在给你我的思路你得帮我想下一步的方案
我的原则是奥卡姆剃刀，不要过于复杂，精炼干净。此外，应严格的面向对象方法。剩余的要求写在项目记忆中。

## 我原来设计的是这些等级：
1, 单个家具：不处理，默认使用家具组来作为最小的分分辨率。但是家具具有几个替身，他们是不可见的几何体，由于家具自身的几何体一定很复杂，所以用简化体做分析与图形运算，其包含
- masspatch，几何代理，也就是一个由多个不布尔的盒子组成的一个家具轮廓，在多数情况下使用其做多项需要家具几何体参与的运算，3d的
- 2d masspatch，一个在考虑中的物体，即物体的3d投影，用于那些仅仅用于平面图2d运算的物体。
- 可供区域，形状应该是一个或多个盒子，用于表达一个家具在使用中所占的全部面积，也就是例如人坐在上面，则平面上就是一椅子加一个人的面积总和。类似这种。也是3d的（我记得有一个论文专门给了这个可供区域的定义方法也是基于BIM，你可能需要找到它。）
2. 家具组：手动传入，基于IFCGROUP，一个group就是一个家具组，这是最小的分析单位
3. inferred group：聚在一起的，且具有同样的【某些特征】的家具组应被自动推断为一组，他们可以被理解为在空间上聚类在一起的家具组们。当前使用region tag来标记属于同一个inferred group的家具组们。这是一个需要放弃的设计，我建议是推断后用这个来缓存标签防止以后重算，但是推断应必须基于几何&图形
4. 柱网：IFCgride的物体组成，形成柱网结构
5. 墙体：IFCwall的物体组成，形成墙体结构
6. 其他家具：依然是家具但是有特殊标记，默认不进入分析，我记得当前设计上会将他们分为专门的一类，funischingelemnt可能，我忘记了
7. 通道，通道本身不是物体，而是家具组之间的间隔，其应有一个相对的最小尺寸，物体可供区域隔离出来的区域，以及inferred group之间隔离出来的区域也是通道。通道应是自动推断，而且根据宽度分出等级，虽然暂时没吊用。

此外，有这些特殊但重要的属性
1,trend：核心属性，用于描述物体的布局趋势和方向性，当前已经有少量实现
2. boundary：用于描述边界情况。其基础情况会是两类：1，地毯，地面上特殊的颜色或者边缘组成的区域；2,边界，具有边界标签并连续的物体，例如低矮的书柜啊之类的，这个我没选好IFC的标签或表达方式，这种边界必然具有出口，也就是断开的地方，但是不会影响连续性，这个需要设计，如何表达，例如区分2d3d，2d连续就算连续。 此外，还有第三类也会产生边界，也就是不带有bounidng标签，而是一个当出现一些几何特征时候，会自动具有的东西。例如，连续且高的沙发，由于椅子背有视觉遮挡的功能，所以也算作边界。
这里应考虑究竟这种情况算不算一种边界，或者将其设置为一种独立的类型
还应考虑，椅子back部具有视觉遮挡的功能，意味着什么？有什么意义，这才能作为一种独立的类型而独立起作用，例如，它会将空间整个分成两个区，人在这个区的时候，被挡住的另一个区不参与总分。或其他的更好的设计
bounding的功能具有mark区域的能力，我当前的设计是，只要物体被套在一个区域内则自动形成一个inferred group（或者一个特殊类型的group，前提是你有特殊用途）。

## 核心指标
这个对于ifcBIM的模型的再建模与分析其目的就是获得包含但不限于以下的核心指标。我只能描述大致是什么但是我没设计出算法来：
1. 家具布局的order程度：同一个inferred group内的家具的一致性与规律性。如果没有multi个iferred group那么就应该是整个空间内家具布局的一致性与规律性，当前的想法是，一个空间至少具有一个inferred group，如果无法形成两个的话，那么所有的家具算在一个里面。目前的想法是基于trend
2. inferred group 之间的的规律性与一致性。基本同上
3. inferred group 自身的规则性，包含其外形是否规则，是否“符合格式塔原则”
4. 家具们的本地的顺从度，顺从指的是他们是否与靠近其且具统一趋势的东西相一致，例如靠近的墙体是鞋的，那么其附近的家具是否是斜的。这个很难，连续量具体怎样搞需要设计，如何处理靠近以及违背与否是困难，我不知道以what为单位，以inferred group？还是单个家具组，或其他
5. 家具与柱网的顺从度，柱网本身有趋势，横平竖直或倾斜旋转，那么家具的布局是否违背了柱网的趋势，还是与其对齐？我同样不知道what为单位。和上面一样，这非常困难。
6. 边界的出现会不会改变什么，例如边界的出现是否会影响家具布局的order程度，或者inferred group之间的规律性与一致性。还有违背柱网的，违背本地的，违背相近家具组的，家具组套上边界边界，会发生什么。可能会对空间的使用和感知产生影响，因此需要考虑其在分析中的作用。这可能不是一个变量，而是很多。这设计非常困难
7. 拓展的分析模型。我认为例如但不限于 贝叶斯分层模型（Spatial Bayesian Hierarchical Models）可能很适合这个分析任务，甚至用其构造指标，因为不像空间句法，我们在尝试让空间的场，空间的结构，自己解释自己，而不是人为构造结构轴线之类，或者你硬生编造出来的指标设计，或生硬的指标设计，所以这很关键。但是我没有想到任何具体用途，但是你需要设计，甚至将这种分析方法带入前面的指标设计中。你应广泛深度阅读与搜索相关的的学术信息与GITHUB项目代码，来帮助你做判断。如果不行，则呀在讨论阶段说明理由。

## 开发目标
### 当前已有的东西
一个导出器SKILL，用于从rhino导出ifc。并汇入BONSAI以确保结构正确
一个基于OSTA逻辑的2d分析框架，尽管当前它的联系已经很弱小了
一个基础的三位分析框架，但是很垃圾
### 我期待什么
1. 一个完整的，基于我上面要求的指标设计详细的档案。这包含了：
1.1 每一个等级的定义，模型法则，例如在ifc中使用的标签或类，具有的特殊标签与属性等。以及几何上的约束，例如在几何上它是什么样子等等，等等。基本的逻辑应该是，在外在有一个漂亮的高模，永远不参与运算只是好看，但是其具有多个特定功能的低模替身或属性，例可供区域，例如用于几何运算的masspatch，例如用于2d的2d投影。如果不存在需要的替身，应提示，有一些替身你很难自己搞搞震，所以生成功能我建议做日程但悬置不做，之后再说，默认依赖余户传入的几何体。最好有一个checklist来检查这些替身是否存在，这可以是GUI的一部分。
1.2 每一个指标的定义，如何计算，如何量化，如何表达。包括其与其他指标的关系，例如顺从度与布局order程度的关系，边界与布局order程度的关系等。注意，我要求是详细档案中，必须包含你设计每一个指标的理由，主要是设计的学术来源。你需要广泛搜索每一个研究领域的学术论文或github代码仓库，找到相关的研究成果，来支持你的设计。你需要在档案中引用这些学术论文或代码仓库，并说明它们如何影响你的设计决策。这里面需要包含带链接的引用。引用的内容包括：你这样做的数学基础是什么，或者哪个心理学论文说到了什么启发了你或你直接用了其模型，什么地信起了作用，或者哪个建筑师说了什么屁话，让你意识到这个指标在建筑师的语境中代表了XX。所以最少你需要探索的领域是环境心理学和建筑学，空间设计。其他按需。
1.3 每一个指标的计算方法，算法设计，数据结构设计，如何处理IFC数据，如何处理几何数据，如何处理图形数据，如何处理属性数据，等等
1.4 考虑到这玩意是用来做统计模型的，设计指标难免有预定义模型以及主观性，所以应有一份元数据的随招标，说明每一项构建指标所用的元数据的信息以及来源，计算方法，表达的意思等

2.一套完整的，内置与blender里的，bonsai插件的拓展。包含
2.1 能够处理IFC数据，并识别1中的所有设计的标签与指标的框架。能够检查替身属性的完整性，能够处理几何数据，以及其他任何为后续计算那些指标的基础的东西。
2.2 计算每一个指标的算法实现，能够处理IFC数据，几何数据，图形数据，属性数据等，并输出结果。正确地配对并提取ifc模型中的元素，超参数等等的东西，来进行计算的玩意
2.3 可视化器。包含：
2.3.1 属性的可视化，例如trend的可视化，可供区域的可视化，等等
2.3.2 指标的可视化。这里应是类似于空间句法，使用热图等方式来可视化你设计出来的那些用于表达的指标，让其可视化。例如用箭头可视化场，可视化每一个分析体素的值，之类的
需要注意的是可视化应当是可交互的，能够让用户选择不同的指标进行查看，并且能够在3D视图中直观地展示这些指标的分布和变化。 而且，其可以缓存，也就是如果模型没变或者没有重新分析则可视化永远存在。但是其应该可以独立开关，也就是不永远依赖于放置一个物体让用户手动显示隐藏，而是可以在插件中有一个开关来控制可视化的显示与隐藏，或叠加显示之类。
2.4 缓存功能，进行了一次分析的结果，应可以被直接写入。blender文件中，如果下次有打开则不需要重新计算，如果模型没有变化则不需要重新计算。缓存的内容应包括指标计算结果，可视化结果，以及任何其他可能需要缓存的数据。 你可以自己设计缓存的机制，例如，究竟是blender的自带缓存，还是你自己设计一个缓存系统，或外部用json，sql等格式来进行缓存，并允许用户手动打开缓存，或者使用数据库等方式来存储缓存数据。你需要考虑缓存的有效性和一致性，确保在模型发生变化时能够正确地更新缓存数据。

3.UI系统，包括
3.1 模型查看，就是看这个IFC模型的基础信息，以及替身的存在性，尺寸，复杂度等等的基础信息，这些基础信息的指标应是有意义的，让用户判断是否进行下一步的分析，所以你需要自己设计。此外，这个插件应与bonsai一起使用才有用（理论上是这样），所以还要检查bonsai是否安装。；
3.2 指标计算界面。一个用于管理和配置指标计算的界面，用户可以选择需要计算的指标，设置相关参数，并查看计算结果。我的设计上是至少需要有勾选功能，例如你有很多指标，那么用户可以选择只计算其中的一部分指标，而不是全部计算。你需要设计一个合理的界面布局，让用户能够方便地选择和配置指标计算的参数，并且能够直观地查看计算结果。此外，这个功能可以配合一个live模式，也就是实时更新计算结果，当用户调整参数时，计算结果会实时更新并显示在界面上。你需要考虑如何实现这个实时更新的功能，以及如何在界面上展示计算结果的变化，这非常适合与勾选功能合用因为如果全算可能太卡（可参考 https://jifto.com/ 这个插件的交互）
3.3 可视化界面。一个用于管理和配置可视化的界面，用户可以选择需要可视化的指标，设置相关参数，并查看可视化结果。
3.4 数据的保存与导出界面。应可以导出表格之类的数据，易于分析
3.5 如有必要增加性能监控界面。

4. skill
4.1 就是rhino的导出skill，这个已经有实现，我们可以在做中调整
4.2 操作这个插件的skill。一个专门给你用的，控制这个插件的技能，能够让你在开发过程中快速调试和测试插件的功能。这个技能我就不列出了，你自己斟酌。这个东西不仅仅可以用于做测试，还可以方便用户的使用。你可以自己设计个mcp之类的，或直接控制脚本，平常没事，但是我希望的是如果在有ui的情况下，那么你可以直接操作工具而不是仅仅的脚本。或者，你操作脚本，但是用户可以在ui中看到你操作的结果或参数的变化等等等等。

## 要求
1. 代码应严格遵循面向对象设计原则，确保模块化、可扩展性和可维护性。每个类和方法应有明确的职责，避免过度耦合。
2. 代码应遵循奥卡姆剃刀原则，尽量简化设计，避免不必要的复杂性。每个功能模块应尽量独立，减少依赖关系。
3. 代码应具有良好的可读性和可维护性，包括清晰的命名、注释和文档。每个类和方法应有详细的注释，说明其功能、输入输出和使用方法。尤其是注释，必须要有，而且要详细，包含方法的注释，以及在代码内部关键逻辑行和逻辑块的注释
4. 考虑性能，做到性能优化
5. 这个应是一个blender插件，你可以自己选择开发语言，开发语言不止一种，我许可你调用blender任何底层的东西。代码可以基于现有的这个项目已有的部分做修改，但是不必拘泥，可以完全存档甚至完全另起炉灶当前的一切已有的代码，我不会干涉。
    6. 这个blender插件理论上必须与BONSAI一起工作，bonsai提供了ifc的必要机能与支持，所以你可以不用自己实现，但是如有必要你可以抛开它，但是必须我同意。但是注意，这个插件应独立与bonsai，你可以抄他代码但是不应是bonsai的同拓展或分支，而是独立的，仅仅是依赖其运行，打开的时候会检查，并要求你安装bonsai。
6. 我希望在设计的时候考虑逻辑的可迁移性质，因为我后续可能会将其迁移到freecad和grasshopper，以及其他平台上。你可以出具一份详细的报告说明大致的迁移逻辑，这应是通用的。
7. 应循序渐进地开发，分步骤的开发，落实功能一个一个，不要一口吃成个胖子，mailstone要经常检查，1必要的时候可以用户来检查。
8. 你应当在设计和开发过程中，广泛参考和借鉴现有的学术研究成果、开源项目和行业实践，确保你的设计和实现具有科学性和可行性。尤其是学术资源方面，你应当广泛搜索相关的学术论文、技术报告和开源项目，了解当前领域的最新进展和最佳实践，并将其应用到你的设计和实现中。你应当在设计文档中引用这些学术资源，并说明它们如何影响你的设计决策。我准备了专门的技能给你下载与搜索文献，如果你需要任何原文，先穷尽skill的能力获取，如果不行可以随时停下向我索取，而不是自己编造，或仅凭abstract和标题就进行编造。一个技巧就是直接去看论文对应的github仓库。
