## Blocking corrections

1. **Authored domain shape must be checked at the actual view seam.** Design lines 27, 46 and 48 require a valid candidate polygon and present authored refs, then reuse the referenced `AnalysisDomain`, but only the inferred mesh gets a projection-equality check. `AnalysisDomain` stores refs rather than a polygon (`features/scene_contract.py:483-501`); `analysis_scene_view` obtains domain *bounds* from those refs (`features/neutral_scene_views.py:50-73,677-688`) and does not check their polygon against the selected outline. Trigger: an authored candidate carries a valid outline but refs that project to a different shape, a hole, or several components. Consequence: the returned exact `scope_polygon` and the view's selected domain disagree while confirmation appears successful. Smallest correction: derive the authored ref polygon with existing `plan_projection`/`component_shape`, require one finite valid polygon and topological equality to the selected outline; if the refs alone define the candidate, use that verified projection as its outline. Refuse absent, duplicate, disjoint or mismatched geometry. Add a focused mismatch/hole case to the planned tests. The inferred support-mesh path is feasible because `plan_projection` unions projected triangles and retains holes/components (`features/geometry_views.py:97-125,526-557`); keep its proposed equality check.

2. **The current-choice compare-and-set and refusal projection are underspecified.** Design line 31 promises an atomic comparison with the current choice version, but its `confirm(candidate_version_id, expected_source_revision, expected_plane_identity, actor, time, reason)` has no expected current-choice token. Two clients can confirm from the same old projection and silently let a later action replace an active choice. Lines 39 and 50 also conflict: line 39 keeps a last valid current choice after a refused attempt, while line 50 makes `analysis_domain`, `scope_polygon` and preview absent on refusal without distinguishing the attempted target from the retained current choice. Smallest correction: include the expected current-choice version/revision in confirmation, compare it atomically with source/plane/candidate/B2 request identity, and expose separate attempt status and current active projection. Requalify the retained choice against the current source/frame/evidence; a rejected or unknown replacement must never silently erase it. Preserve both incompatible events and refuse promotion on unresolved conflict. Test concurrent stale confirmation and refused replacement with a still-valid current domain. Historical lifecycle experiments are design evidence, not a production event reducer (`docs/project/evidence/d6-space-field-candidate-set-lifecycle-final-owner-decision.md`; status amendment).

3. **Make the one-plane frame gate supplyable by the caller.** Design line 46 requires a “known level/single-plane scope” and cites unknown authored floor datum among reasons to refuse real S1. The accepted B2 request already binds an explicit scene plane, metre units, caller datum and cut (`features/_semantic_enclosure.py:18-51`); the frozen real request supplies those values. Trigger: a geometrically qualified simple inferred or user-authored scope with a consistent explicit caller frame but no authored floor metadata. Consequence: the first useful single-room path can be refused for missing metadata that the request can supply. Smallest correction: define “known” as an explicit, verified scene/caller plane and datum for this session; absence of an authored floor datum alone is not invalid geometry. Keep the real S1 refused for concrete unresolved local aperture refs A11/A12 (both listed in frozen `run_007/semantic_result.json`) and any still-unverified geometry/parity evidence relevant to activation. Do not treat confirmation as evidence that repairs those failures.

## Accepted boundary and next decision

The document correctly distinguishes one provisional S1 from five diagnostic contours, keeps wall/column mass in physical occupancy, preserves default-closed door/window closure as an authorized scenario without changing genuine unfilled apertures, requires explicit selection and confirmation, and makes hover/read-only preview non-authoritative. The private B2 helper still hardcodes promotion refusal (`features/_semantic_enclosure.py:380-421`); its opted-in wrapper adds only a diagnostic child (`features/neutral_scene_views.py:32-45`). No production selector or UI exists. The proposed session child fits the existing `NeutralSceneV2.analysis_domain` and `MeshGeometry3D` fields (`features/scene_contract.py:483-501,592-641,892-929`), with a derived mesh kept out of source objects. The narrow result must not expose its full view: `evaluate_scene` accepts a view (`features/scene_evaluator.py:67-76`), and its negative-space and sampled-domain paths can use a rectangle/all cells after domain availability (`:4305-4328,4616-4644`). The design's hard stop before formal field, route and topology therefore remains necessary. No qualified domain must remain `not_available`; diagnostic bounds cannot substitute for one.

Owner recommendations remain three small decisions: approve a revised D1 session authority contract with a real current-choice token and retained-active/refused-attempt semantics; approve revised D2 exact authored/inferred projection qualification and an explicit caller-frame route; approve D3's accessible private preview and formal-evaluator stop. These resolve only this session seam. A1 public persistence, A2 general undo/authority, A3 automatic selection, B1 general frame policy, B3 field backend and B4 live integration remain deferred; B5's narrow status separation and the later private B2 acceptance are not broader approvals. Planned positive/negative tests in design line 64 are appropriate after these corrections and remain unrun.
