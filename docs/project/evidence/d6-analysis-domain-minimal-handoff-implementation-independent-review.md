## Actionable findings

1. **[P1] An unconfirmed session snapshot can produce an active domain.** `domain_handoff` copies `session_state.current_version_id`, `current_binding` and `revision` directly (`features/_analysis_domain_handoff.py:217-223`), then activates that projection (`:305-334`) without proving it came from a confirm event. Trigger: pass a mapping with the current candidate/version and published provenance hashes, `revision=1`, and `events=[]`, then call the private entry with `action=None`. The reproduction returns `current.status=active` and a non-null `analysis_domain` with no confirmation event. This violates D1's explicit confirmation gate and makes the append-only log non-authoritative. Smallest correction: make one trusted session transition state the only source of current authority, or validate/reduce the event history against the claimed projection before handoff; reject inconsistent externally supplied snapshots. Add a composed no-confirmation forged/inconsistent-state regression.

2. **[P1] A later conflicting authored candidate leaves an inferred domain consumable.** On confirm, incompatible authored/inferred outlines require an acknowledgement (`features/_analysis_domain_handoff.py:278-284`), but the read-only current path checks only the active candidate's old binding (`:305-334`). Trigger: confirm a single inferred B2 S1; on the next call, add a different authored candidate while keeping the scene and B2 request unchanged. The reproduction returns `current.status=active`, with both the new authored candidate and the old inferred one visible, and still returns the inferred `AnalysisDomain`. The accepted D1/D2 rule keeps an unresolved authored/inferred disagreement from downstream handoff; a candidate-set change must not bypass it. Smallest correction: check current catalog disagreements on every handoff (or bind/revalidate the relevant candidate-set identity), preserve both candidates and set current to conflict/not-available until a fresh qualified choice records the disagreement. Test this composed later-arrival sequence and a non-conflicting later arrival.

3. **[P2] An authored domain can remove unrelated physical furniture from occupancy.** `_project_authored` validates geometry refs and shape but not the domain's `source_id` role (`features/_analysis_domain_handoff.py:68-87`). The existing view treats any exact matched non-wall/non-column source ID as domain shell (`features/neutral_scene_views.py:691-753`) and excludes it from `physical_occupancy` (`:147-154`). Trigger: give a valid one-polygon authored domain the source ID and mesh ref of a furniture object. Confirmation succeeds; the reproduction shows `left_table` in the ordinary source view's occupancy but absent from the private handoff preview. Source objects are unchanged, yet the bounded occupancy input is altered, contrary to D2's occupancy preservation. Smallest correction: qualify authored domain source identity as actual eligible domain support before using it as a shell, or refuse a candidate whose source role would suppress physical mass such as furniture; keep legitimate spatial/floor support behavior. Test the accepted authored support and the furniture-source negative case.
